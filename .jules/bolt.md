## 2026-09-14 - Hoist static Regexes, eliminate intermediate line arrays, lazy-allocate flaggedReasons, and inline loop metrics in analyzeLogs
**Learning:** In client-side JS log parsing loops processing tens of thousands of lines, creating intermediate line-filtering arrays (`split().filter()`), re-instantiating regexes or `Object.entries()` per invocation, allocating array instances on every un-flagged line, and doing post-processing filters on result arrays introduce significant memory garbage collection and execution overhead.
**Action:** Always hoist static Regular Expressions and pre-flatten constant rule objects at module scope, iterate over split lines in a single index-based `for` loop with inline empty checks, lazy-allocate line-specific arrays, cache object key lookups, and track summary counters inline during the loop.
